# 워크플로우 생성 및 추가 메커니즘

"워크플로우가 추가되는 방식"은 **같은 앱 내에서의 버전 추가**와 **새로운 앱을 통한 로직 추가** 두 가지 관점으로 나뉩니다.

## 1. 같은 앱 내에서의 추가: 버전 관리 (Versioning)

앱을 처음 생성하면 기본적으로 **단 하나의 'Draft(초안)' 워크플로우**가 생성됩니다. 그 후 "워크플로우가 늘어나는 것"은 주로 **버전(Version)**이 쌓이는 과정을 의미합니다.

- **동작 방식**: 사용자가 캔버스에서 **"배포(Publish)"** 버튼을 클릭할 때마다 발생합니다.
- **프로세스**:
  1.  백엔드 시스템이 현재의 **Draft(작업 중인 상태)**를 복제합니다.
  2.  복제된 데이터에 `2024-01-01 12:00:00`과 같은 **타임스탬프 버전 정보**를 부여합니다.
  3.  이를 `workflows` 테이블에 새로운 행(Record)으로 저장합니다.
- **결과**: 앱은 `Draft` 1개와 `Published History` N개를 가지게 됩니다.

## 2. 워크플로우 버전의 종류 (Version Types)

워크플로우 버전은 크게 **Draft(초안)**와 **Published(배포)** 두 가지로 나뉩니다.

### 2.1. Draft (초안) 버전

- **식별자**: 문자열 `"draft"`
- **설명**: 개발자가 현재 캔버스에서 편집 중인 **단 하나의** 작업용 버전입니다.
- **특징**: 앱당 오직 하나만 존재하며, 수정 시 계속 내용이 덮어씌워집니다 (Mutable).

### 2.2. Published (배포) 버전

- **식별자**: **타임스탬프 문자열** (예: `2024-01-01 12:00:00`)
- **설명**: 사용자가 "배포" 버튼을 눌렀을 때 생성된 스냅샷입니다.
- **특징**:
  - 한 번 생성되면 절대 수정되지 않습니다 (Immutable).
  - 여러 개가 존재할 수 있으며, 이력을 구성합니다.
  - 실제 앱 실행(Run)은 이 중 하나의 버전을 기준으로 동작합니다.

## 3. 다른 로직의 추가: 새 앱 생성 (New App)

만약 기존 로직과 병렬로 실행되거나, 완전히 다른 목적을 가진 워크플로우를 만들고 싶다면 **새로운 앱**을 생성해야 합니다.

- **이유**: **구조상** **하나의 앱은 동시에 하나의 '활성 Draft'만 가질 수 있기 때문**입니다.
- **방법**: 대시보드에서 "Create New App"을 통해 별도의 앱 컨테이너를 만듭니다.
- **활용**: 서로 다른 앱으로 만든 워크플로우들은 **"Workflow as Tool"** 기능을 통해, 마치 레고 블록처럼 서로를 호출하거나 조합하여 사용할 수 있습니다.

---

**요약:**

- **"Draft"**: 작업 중인 단 하나의 캔버스.
- **"Published"**: 배포된 과거 이력(History).
- **"New App"**: 완전히 새로운 로직의 추가.
