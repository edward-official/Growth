# Networking & Security — Organized Q&A Summary

## 1. SSH vs TLS (big picture)

**Q: How are SSH and TLS different?**
**A:**

* **SSH** = secure *remote control* (log in, run commands, move files).
* **TLS** = secure *communication* (protects data sent over the network).

**One-liner:**

> SSH secures access to machines; TLS secures data between applications.


**Q: Does SSH need TLS to be secure?**
**A:**
No. SSH is already a complete secure protocol.
It has its own:

* Encryption
* Authentication
* Integrity checks
* Key exchange

TLS is **not a prerequisite** for secure data transfer.


**Q: Can I say SSH “contains” the ability of TLS?**
**A:**
Yes, **conceptually**.

Correct phrasing:

> SSH includes secure-communication capabilities similar to TLS.

Incorrect phrasing:

* SSH uses TLS ❌
* SSH is built on TLS ❌

SSH and TLS are **independent protocols**.


## 2. TLS core idea

**Q: What is the core concept of TLS?**
**A:**
Protecting communication over an untrusted network.

TLS provides:

* Confidentiality (encryption)
* Integrity (no tampering)
* Authentication (server identity)

TLS does **not** define application behavior — it only protects data in transit.


## 3. CA (Certificate Authority)

**Q: What is a CA?**
**A:**
A **Certificate Authority** is a trusted third party that verifies identities and signs certificates.

TLS works because:

* Your system already trusts root CAs
* Servers present certificates signed by those CAs
* Clients verify the certificate chain

**Mental model:**
CA = passport office
Certificate = passport
Browser/OS = border control


## 4. FTP, SCP, SFTP

**Q: What is FTP?**
**A:**
An old file-transfer protocol that sends:

* Usernames ❌
* Passwords ❌
* Data ❌
  in **plain text**.

FTP is insecure and mostly obsolete.


**Q: What are SCP and SFTP?**
**A:**
Both are **file-transfer protocols that run over SSH**.

* **SCP**: simple, non-interactive copy
* **SFTP**: interactive file management

Important:

* SFTP ≠ FTP over TLS
* SFTP has nothing to do with FTP internally


## 5. Packets vs Sockets

**Q: What is a packet?**
**A:**
A **packet** is a small unit of data sent across the network.

* Created and handled by the OS & network stack
* Can be lost, reordered, retransmitted
* Applications usually never see packets

**Mental model:**
Packet = envelope on the wire


**Q: What is a socket?**
**A:**
A **socket** is the interface a program uses to talk to the network.

* File-like object (file descriptor)
* Uses `read()` / `write()`
* Represents a communication endpoint

**Mental model:**
Socket = doorway between your program and the network


**Q: Are sockets files?**
**A:**
They are **file-like**, not regular files.

| File           | Socket           |
| -------------- | ---------------- |
| Stored on disk | Live data stream |
| Seekable       | Not seekable     |
| Persistent     | Ephemeral        |


**Q: Can I say sockets are the “entrances” of the network?**
**A:**
Yes — conceptually correct.

More precise:

> Sockets are the interface between programs and the OS networking stack.


## 6. How packets are generated

**Q: How is a packet created?**
**A:**
Your program never creates packets directly.

Flow:

1. App writes bytes to a socket
2. OS buffers the data
3. TCP/UDP splits it
4. IP wraps it with addresses
5. NIC sends it onto the network

Packets are created **automatically by the OS kernel**.


## 7. TCP vs UDP

**Q: How are TCP and UDP different?**
**A:**

| TCP               | UDP           |
| ----------------- | ------------- |
| Reliable          | Best-effort   |
| Ordered           | Unordered     |
| Retries lost data | No retries    |
| Slower            | Faster        |
| Stream-based      | Message-based |


**Q: Is TCP for reliability and UDP for speed?**
**A:**
Yes — that’s the correct core understanding.

Polished version:

> TCP trades speed for reliability; UDP trades reliability for low latency.


**Q: Do TCP and UDP care about encryption?**
**A:**
No. Not at all.

TCP/UDP:

* Move bytes
* Don’t know or care if data is encrypted

Encryption happens **above** them (TLS, SSH, QUIC).


## 8. TCP/UDP vs TLS

**Q: How are TCP/UDP and TLS different?**
**A:**

* **TCP/UDP**: how data is delivered
* **TLS**: how data is protected

TCP/UDP = delivery mechanics
TLS = security wrapper

They solve **different problems** and work together.


## Final mental stack (lock this in)

Packets → TCP/UDP → Sockets → TLS / SSH → Applications

If this stack feels clear in your head, your networking foundation is solid.


**One final sentence that sums everything up:**

> TCP/UDP move bytes, TLS protects bytes, SSH uses protected bytes to let you operate machines.
