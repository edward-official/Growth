CPU는 1초에 1억번 연산하므로 문제를 잘 읽고 문제의 요구 사항을 만족시키려면 어떤 알고리즘을 써야할 지 생각을 해야합니다. (데이터 개수에 따른 시간 복잡도를 생각을 해야한다.)
또 라이브러리를 사용한다면 내장 함수의 시간 복잡도 또한 고려해야합니다.

하지만 입력 크기에 맞는 알고리즘을 선택해 연산량 자체를 줄이더라도 여전히 시간 초과가 발생할 수 있습니다.
따라서 다음과 같은 전략을 익혀두어야 합니다.

# 1. 문자열 처리 최적화

## 1) 문자열 합치기: `+` 대신 `"".join()`

* 파이썬 문자열은 immutable(불변)이다.
* `+`로 문자열을 반복해서 합치면 매번 새로운 문자열을 생성한다.
* 이 경우 시간 복잡도가 사실상 O(n²)에 가까워질 수 있다.
* 여러 문자열을 합칠 때는 반드시 `"".join(iterable)`을 사용한다.
* `join()`은 내부적으로 한 번에 처리하므로 효율적이다.


# 2. 조건문 최적화 (Short-circuit 활용)

* `and`, `or`는 단락 평가(short-circuit)를 한다.

  * `and`: 앞이 False이면 뒤를 실행하지 않는다.
  * `or`: 앞이 True이면 뒤를 실행하지 않는다.
* 실행 비용이 적은 조건을 앞에 배치하는 것이 유리하다.
* 다중 조건에서는 계산량이 적은 것부터 평가하도록 작성한다.


# 3. 슬라이싱 활용

* 문법: `a[start:end:step]`

  * start는 포함, end는 미포함
  * step 기본값은 1
  * 음수 step 사용 가능 (역순 탐색)
* 리스트, 튜플, 문자열 등 iterable 객체에 사용 가능
* 2차원 배열에도 적용 가능
* 불필요한 반복문을 줄이고 코드 길이를 단축할 수 있다.


# 4. 표준 라이브러리 적극 활용

직접 구현하는 것보다 표준 라이브러리를 사용하는 것이:

* 더 빠르고
* 더 안전하며
* 코드도 간결하다.

자주 쓰는 라이브러리:

* `heapq`: 최소 힙 (우선순위 큐, 다익스트라 등)
* `collections`

  * `Counter`: 빈도 계산
  * `deque`: 빠른 양방향 큐
* `itertools`

  * permutations
  * combinations
  * 중복 순열, 중복 조합 등
* `math`: gcd, lcm, sqrt, log, 상수 등
* `bisect`: 이진 탐색

코딩 테스트에서는 외부 라이브러리는 제한될 수 있으므로 표준 라이브러리 위주로 사용한다.


# 5. 리스트 컴프리헨션

기존 방식:

```python
data = []
for i in range(1, 11):
    data.append(i)
```

컴프리헨션:

```python
[i for i in range(1, 11)]
```

특징:

* 한 줄로 표현 가능
* 선언 + 반복 + 할당이 한 번에 이루어짐
* 가독성과 작성 속도 향상
* 조건도 추가 가능:

```python
[i for i in range(11) if i % 2 == 0]
```

중첩 조건도 가능하다.

시간 복잡도는 동일하게 O(n)이지만 코드가 간결해진다.


# 6. 제너레이터

리스트 컴프리헨션과 문법은 유사하지만 괄호를 사용한다:

```python
(i for i in range(10))
```

차이점:

| 항목     | 리스트 컴프리헨션 | 제너레이터          |
| ------ | --------- | -------------- |
| 메모리    | 전체 데이터 저장 | 값이 필요할 때 생성    |
| 실행 방식  | 즉시 평가     | next() 호출 시 평가 |
| 공간 복잡도 | O(n)      | O(1)           |

대량 데이터(예: 100만 개 이상)에서는 메모리 절약 효과가 매우 크다.

단점:

* 실행 결과를 저장하지 않음
* 여러 번 사용하려면 다시 생성해야 함

실행 시간은 대체로 비슷하지만, 메모리 사용량은 큰 차이가 난다.


# 7. 데이터 흐름 최적화 (중복 제거)

잘못된 예:

```python
answer = data
for i in range(len(answer)):
    temp = answer[i] * answer[i]
    answer[i] = temp
```

문제점:

* 불필요한 변수 사용
* 원본 데이터와 참조 공유 가능성
* 논리 흐름이 분산됨

개선:

```python
return [i * i for i in data]
```

핵심:

* 중복 변수 제거
* 불필요한 복사 방지
* 한 번의 흐름으로 처리
* 논리를 간결하게 유지
