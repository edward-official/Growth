# Chapter 4. 문자열 효율적으로 다루기

## 1. 문자열의 본질과 파이썬의 처리 방식

### 문자열이란? (Section 4.1.1)

- **데이터 인식의 차이**: 사람이 보는 문자열과 컴퓨터가 받아들이는 데이터 사이에는 큰 차이가 있습니다. 모든 것을 숫자로 이해하는 컴퓨터를 위해 '문자를 숫자로 변환하는 과정'이 필요하며, 이때 가장 대표적인 **유니코드(Unicode)** 체계를 사용합니다.
- **배열로서의 문자열**: 파이썬에서 문자열을 선언하면 각 문자에 정보를 담기 위해 암묵적으로 **배열**로 관리합니다. 기존의 리스트(`[]`)처럼 명시적으로 선언하지는 않지만, 메모리상에서는 배열처럼 취급됩니다.
- **메모리 특징 (Immutable)**: 파이썬의 문자열은 **상수(const)**로 취급됩니다. 즉, 조회는 가능하지만 인덱스에 직접 접근하여 값을 수정할 수는 없습니다.
- 문자열을 합치거나 수정하는 연산(`+` 등)을 수행하면 기존 문자열을 바꾸는 것이 아니라, **매번 새로운 메모리 공간에 문자열을 생성**하므로 비효율적일 수 있음을 유의해야 합니다.

```python
sample = "Programmers is good"
print(sample[0])    # 'P' 출력
print(sample[15:])  # 'good' 슬라이싱 지원

# sample[15:] = "awesome"
# 위 코드는 에러 발생 (문자열은 상수라 변경 불가)

```

## 2. 문자열 코딩 테스트 8가지 주요 유형

### (1) 문자열 뒤집기 (Palindrome 응용)

- **기본**: 슬라이싱 `[::-1]`을 사용하면 통째로 뒤집기가 매우 쉽습니다.
- **응용**: 팰린드롬(거꾸로 읽어도 같은 단어) 확인 시 자주 쓰입니다.
- **심화**: Level 1 이상의 문제에서는 단순히 전체를 뒤집는 것이 아니라, **특정 부분만 뒤집기** 혹은 **상황에 맞춰 뒤집기**를 요구합니다. 이때는 `for`문, **투 포인터(Two Pointers)** 등을 적절히 섞어서 구현해야 합니다.

### (2) 아스키(ASCII) 코드 다루기

- C언어 경험이 있다면 익숙하겠지만, 파이썬에서도 문자를 숫자로 계산한 뒤 다시 문자로 치환하는 문제가 자주 나옵니다.
- **핵심 함수**:
- `ord(문자)`: 문자를 아스키 숫자로 변환
- `chr(숫자)`: 숫자를 문자로 변환

- **활용**: 알파벳 순회나 특정 거리만큼 떨어진 알파벳 찾기 등에 필수입니다.

### (3) 진법 변경하기

- 10진수를 다른 진수로 바꾸면 그 결과값은 **문자열**이 됩니다. 숫자의 자리 하나하나가 중요하기 때문에 이 변환 코드는 반드시 외워두는 것이 좋습니다.
- **내장 함수**: `bin()`, `oct()`, `hex()`
- **사용자 정의 변환 함수 (반드시 숙지)**:

```python
def radixChange(num, radix):
    if num == 0: return '0'
    nums = []
    while num:
        # num을 radix로 나눈 몫과 나머지를 동시에 구함
        num, digit = divmod(num, radix)
        nums.append(str(digit)) # 나머지를 리스트에 추가

    # 뒤집어서 합쳐야 올바른 진법 결과가 나옴
    return ''.join(reversed(nums))

```

### (4) 애너그램(Anagram) 확인하기

- 두 단어의 철자 구성이 같은지 확인하는 유형입니다.
- **방법 A**: 두 문자열을 정렬(`sorted()`)하여 비교 → 시간 복잡도 $O(N \log N)$
- **방법 B**: **해시 테이블(딕셔너리)**을 활용해 각 단어의 빈도수를 계산 → 시간 복잡도 $O(N)$. 데이터가 많을 때 훨씬 효율적입니다.

### (5) 원하는 문자 찾기 (검색)

- 실무에서도 가장 많이 쓰이는 유형입니다. 단순히 `.find()`를 무작정 쓰기보다는 문제에서 주어진 조건(문자열의 크기, 탐색 범위)에 따라 최적의 방법을 찾아야 합니다. 불필요한 탐색 범위를 빠르게 제거하는 것이 핵심입니다.

### (6) 기준에 맞춰 재정렬하기

- 알파벳과 숫자가 섞여 있을 때 특정 기준(예: 숫자 합산 후 알파벳 정렬)에 따라 데이터를 가공하는 유형입니다. `collections` 라이브러리의 `Counter` 등을 활용해 빈도를 계산하거나 가공하는 능력이 필요합니다.

### (7) 문자열 치환하기 (Replace)

- 특정 단어를 찾아 바꾸는 유형입니다. 직접 구현하려다 보면 코드가 매우 복잡해지기 쉬우므로 파이썬 내장 함수인 `.replace()`를 적극 활용하는 것이 좋습니다.

### (8) 정규 표현식(Regular Expression)

- 문자열 조작의 "최종 보스"입니다. 한 줄로 복잡한 패턴 매칭과 치환이 가능하여, 복잡한 조건문과 반복문을 획기적으로 줄여줍니다. 상세한 문법과 활용법은 **'3. 정규표현식'** 섹션에서 다룹니다.

## 3. 정규표현식(Regular Expression)

정규표현식은 특정한 규칙을 가진 문자열의 집합을 표현하기 위해 사용하는 **형식 언어**입니다. 방대한 텍스트 데이터 내에서 특정 패턴을 추출하거나 치환해야 할 때, 복잡한 반복문과 조건문 없이도 간결하게 목적을 달성할 수 있는 강력한 도구입니다.

### (1) 정규표현식의 필요성과 개념

복잡한 문자열 구조에서 특정 데이터(예: 전화번호, 이메일, 특정 형식의 ID 등)를 추출해야 할 때, 정규표현식을 모른다면 문자열을 일일이 자르고 분할하는 번거로운 과정을 거쳐야 합니다. 하지만 정규표현식을 사용하면 단 한 줄의 패턴만으로 원하는 데이터를 정확히 특정할 수 있습니다.

**전화번호 추출 예시 패턴:**

```text
0\d{1,2}[ -]?\d{3,4}[ -]?\d{3,4}
```

위와 같은 기호의 조합이 정규표현식이며, 이는 약속된 기호들로 구성된 일종의 규칙입니다.

### (2) 주요 정규표현식 기호 및 의미

정규표현식은 원리에 의한 추론보다는 약속된 기호의 의미를 숙지하는 것이 중요합니다.

#### 기본 메타 문자

| 표현식      | 의미                                                         |
| :---------- | :----------------------------------------------------------- |
| **^X**      | 문자열이 **X**로 시작함                                      |
| **X$**      | 문자열이 **X**로 끝남                                        |
| **.**       | 임의의 **한 문자**를 의미                                    |
| **X\***     | 문자 **X**가 0번 이상 반복됨                                 |
| **X+**      | 문자 **X**가 1번 이상 반복됨                                 |
| **X?**      | 문자 **X**가 존재할 수도, 존재하지 않을 수도 있음 (0 또는 1) |
| **X\|Y**    | 문자 **X** 또는 **Y**가 존재함                               |
| **(X)**     | 문자 **X**를 그룹으로 처리함                                 |
| **X{n}**    | 문자 **X**가 정확히 **n번** 반복됨                           |
| **X{n,}**   | 문자 **X**가 **n번 이상** 반복됨                             |
| **X{n, m}** | 문자 **X**가 **n번 이상 m번 이하** 반복됨                    |
| **[XY]**    | 문자 **X** 또는 **Y** 중 하나를 의미                         |
| **[^X]**    | 문자 **X**를 제외한 문자를 의미                              |
| **[A-Z]**   | **A**부터 **Z**까지의 문자 범위를 의미                       |

#### 자주 사용하는 문자 클래스

| 표기법 | 의미                                         |
| :----- | :------------------------------------------- |
| **\d** | 숫자와 매칭 `[0-9]`                          |
| **\D** | 숫자가 아닌 것과 매칭 `[^0-9]`               |
| **\s** | 공백 문자(whitespace)와 매칭 `[ \t\n\r\f\v]` |
| **\S** | 공백 문자가 아닌 것과 매칭                   |
| **\w** | 문자 및 숫자와 매칭 `[a-zA-Z0-9_]`           |
| **\W** | 문자 및 숫자가 아닌 것과 매칭                |

### (3) 예시 코드 분석: 전화번호 패턴

가장 대표적인 예시인 전화번호 추출 패턴을 분석하면 다음과 같습니다.

**패턴:** `0\d{1,2}[ -]?\d{3,4}[ -]?\d{3,4}`

1.  **`0`**: 반드시 숫자 '0'으로 시작해야 함을 의미합니다.
2.  **`\d{1,2}`**: 숫자(`\d`)가 1개 또는 2개 등장함을 의미합니다. (지역번호 또는 앞자리 식별번호)
3.  **`[ -]?`**: 공백(` `) 또는 하이픈(`-`)이 존재할 수도 있고 없을 수도 있음을 의미합니다.
4.  **`\d{3,4}`**: 숫자가 3개 또는 4개 연속으로 등장함을 의미합니다.
5.  **`[ -]?`**: 다시 공백이나 하이픈의 유무를 체크합니다.
6.  **`\d{3,4}`**: 마지막으로 숫자가 3개 또는 4개 등장하며 마무리됩니다.

### (4) 주의사항: 시간 복잡도

정규표현식의 시간 복잡도는 패턴의 설계 방식과 입력 문자열의 상태에 따라 매우 가변적입니다.

- **최선의 경우**: $O(n)$ 수준의 선형 시간에 탐색이 완료됩니다.
- **최악의 경우**: 복잡한 역추적(Backtracking)이 발생하는 패턴에서는 시간 복잡도가 지수 시간($O(2^n)$)까지 치솟을 수 있습니다.

따라서 매우 방대한 텍스트를 처리할 때는 정규표현식에만 의존하기보다, 전처리를 통해 탐색 범위를 좁히거나 패턴을 최적화하는 과정이 반드시 필요합니다.

## 4. 요약 및 관점의 전환 (Section 4.1.2)

- 지금까지 배운 것은 **'문자열을 숫자로 치환하여 생각한다'**는 기본기입니다.
- 더 나아가면 문자열 안에 실행 코드를 담아 실행하는 `eval()` 함수처럼, 문자열을 단순한 '글자 묶음'이 아니라 **의미를 가진 데이터의 한 형태**로 보아야 합니다.
- 문자열 문제의 본질은 **"주어진 데이터를 조작하여 원하는 모양을 만든 다음, 필요한 정보를 수집하는 것"**입니다.
