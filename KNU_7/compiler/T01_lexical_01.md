## 키워드 정리

### 1. 어휘 분석의 기본 단위

- **Lexeme (어휘소)**: 소스 프로그램에서 토큰의 패턴과 일치하는 문자들의 연속입니다. (예: `x`, `=`, `21`) .

- **Token (토큰)**: 어휘소의 종류를 나타내는 추상적 기호인 토큰 이름과 선택적인 속성값으로 구성된 쌍 `<Token_name, Attribute_value>`입니다.

- **Pattern (패턴)**: 특정 토큰 타입에 속하는 어휘소들이 가질 수 있는 규칙을 의미합니다.

### 2. 정규 표현식 (Regular Expression, RE)

토큰의 패턴을 공식적으로 기술하기 위한 수단입니다.

- **기본 연산**:
- **Alternation (선택)**: $x|y$ ($L(x) \cup L(y)$).

- **Concatenation (결합)**: $xy$ ($L(x)L(y)$).

- **Kleene Star (반복)**: $x^*$ (0회 이상 반복).

- **우선순위**: 반복(Closure) > 결합(Concatenation) > 선택(Alternation) 순으로 적용됩니다.

### 3. 유한 오토마타 (Finite Automata, FA)

정규 표현식으로 기술된 패턴을 코드로 구현하여 실제 입력을 인식(Recognizer)하는 모델입니다.

- **DFA (Deterministic Finite Automata)**: 각 상태에서 입력 기호에 대해 이동할 수 있는 다음 상태가 오직 하나로 정해져 있으며, $\epsilon$(빈 문자열) 이동이 없습니다.

- **NFA (Non-deterministic Finite Automata)**: 하나의 입력에 대해 여러 경로를 가질 수 있거나 입력 소비 없이 이동하는 $\epsilon$-transition을 포함할 수 있습니다.

### 4. 스캐너 자동 생성 프로세스

**스캐너(Scanner)**는 컴파일러의 첫 번째 단계인 **어휘 분석(Lexical Analysis)**을 수행하는 프로그램입니다. 소스 코드라는 거대한 문자열을 읽어서 의미 있는 최소 단위인 **토큰(Token)**으로 분해하는 역할을 합니다.

수업 자료는 정규 표현식을 최소 상태의 DFA로 변환하여 스캐너를 자동으로 구축하는 **'Cycle of Constructions'**를 강조합니다:

1.  **RE → NFA**: **Thompson's construction** 알고리즘을 사용하여 정규 표현식의 구조에 따라 NFA를 구축합니다.

2.  **NFA → DFA**: **Subset construction** 알고리즘을 통해 NFA를 시뮬레이션하는 DFA를 만듭니다.

3.  **DFA → Minimal DFA**: **State minimization** (Hopcroft's algorithm 등)을 통해 불필요한 상태를 줄여 효율적인 스캐너를 생성합니다.

## 토큰의 구성 요소

컴파일러의 **스캐너(Scanner)**가 소스 코드를 읽어서 의미 있는 단위로 쪼갤 때, 단순히 글자만 잘라내는 것이 아니라 후속 단계인 **파서(Parser)**가 처리하기 좋게 **구조화된 정보**로 변환합니다. 그 결과물이 바로 `<Token_name, Attribute_value>` 쌍입니다.

### 1. 구성 요소의 정의

- **Token Name (토큰 이름)**:
- 해당 어휘소가 어떤 **카테고리**에 속하는지를 나타내는 추상적인 기호입니다.

- 파서가 문법 구조를 판단할 때 사용하는 핵심 정보입니다.

- 예: `ID` (식별자), `INTLITERAL` (정수 리터럴), `IF` (예약어 `if`), `ASSIGN` (대입 연산자 `=`).

- **Attribute Value (속성값)**:
- 같은 토큰 이름 내에서 **개별 어휘소를 구별**하기 위한 추가 정보입니다.

- 심볼 테이블(Symbol Table)의 엔트리 주소나 실제 숫자 값 등이 저장됩니다.

### 2. 구체적인 예시 ($x = 21$)

이 코드가 입력되었을 때 스캐너가 생성하는 토큰 쌍은 다음과 같습니다:

| 어휘소 (Lexeme) | 토큰 이름 (Token Name) | 속성값 (Attribute Value) | 최종 토큰 표현     |
| --------------- | ---------------------- | ------------------------ | ------------------ |
| `x`             | `id` (식별자)          | `0` (심볼 테이블 인덱스) | `<id, 0>`          |
| `=`             | `ASSIGN` (대입)        | (없음/생략 가능)         | `<=>`              |
| `21`            | `intliteral` (정수)    | `21` (상수 값)           | `<intliteral, 21>` |

### 3. 왜 속성값이 필요한가?

- **예약어의 경우**: `if`나 `else` 같은 키워드는 그 자체로 유일하므로 별도의 속성값이 없어도 파서가 무엇인지 알 수 있습니다.

- **식별자나 숫자의 경우**: 문법적으로는 똑같은 `id` 토큰이지만, 실제 프로그램 로직에서는 변수 `x`와 변수 `y`를 구분해야 합니다. 따라서 속성값에 그 구체적인 정보를 담아 전달하는 것입니다.

## 정규 표현식

컴퓨터 과학의 **컴파일러** 설계에서 **정규 표현식(Regular Expression, RE)**은 소스 코드에 나타나는 단어(토큰)들의 **패턴을 정의하는 공식적인 규칙**을 의미합니다.

쉽게 말해, "이 단어는 변수명이다", "이것은 숫자다"라고 판단할 수 있는 **'설계 도면'**과 같습니다. 수업 자료에 명시된 실제 예시들을 통해 설명해 드릴게요.

### 1. 정규 표현식의 실제 예시

예시 A: 식별자 (Identifier) 패턴

우리가 프로그래밍 언어에서 변수명을 만들 때 보통 "첫 글자는 영문자나 언더바(\_)로 시작하고, 그 뒤에는 영문자, 숫자, 언더바가 올 수 있다"는 규칙을 가집니다. 이를 RE로 표현하면 다음과 같습니다.

- **RE**: `letter (letter | digit)*`
- **설명**: `letter`로 시작하고, 뒤이어 `letter` 또는 `digit`가 0번 이상 반복(`*`)된다는 뜻입니다.

- **일치하는 단어(Lexemes)**: `sum`, `_sum`, `KNU_2023`, `HelloWorld`

예시 B: 정수 (Integer) 패턴

"첫 글자는 숫자이고, 그 뒤에 숫자가 0개 이상 붙는다"는 규칙입니다.

- **RE**: `digit digit*` (또는 shorthand로 `digit+` )

- **설명**: `digit`가 최소 한 번 이상 나타나야 함을 의미합니다.

- **일치하는 단어(Lexemes)**: `0`, `1`, `101`, `2023`

예시 C: RISC-V 레지스터 패턴

"문자 'r'로 시작하고 그 뒤에 숫자가 최소 하나 이상 붙는다"는 규칙입니다.

- **RE**: `r (0|1|2|...|9) (0|1|2|...|9)*`
- **일치하는 단어(Lexemes)**: `r0`, `r1`, `r17`, `r99`

### 2. 왜 RE를 NFA로 바꾸나요? (Thompson's construction의 목적)

정규 표현식(`RE`)은 인간이 이해하기 편한 **'규칙'**일 뿐, 컴퓨터가 이 규칙을 보고 바로 "이 단어는 숫자가 맞네!"라고 판단하는 로직을 돌리기는 어렵습니다.

그래서 다음과 같은 과정을 거칩니다:

1.  **RE (설계도)**: `a | b` (a 또는 b라는 규칙)

2.  **NFA (회로도)**: Thompson's construction 알고리즘을 사용하여 RE의 각 기호와 연산자를 **상태(State)**와 **전이(Transition)**를 가진 그래프 형태로 바꿉니다.

3.  **DFA/Code (실제 기계)**: 이 그래프를 바탕으로 실제 소스 코드를 한 글자씩 읽으며 판별하는 실행 코드를 생성합니다.

4.  Thompson's Construction의 기본 단위

이 알고리즘은 RE의 기본 구성 요소를 다음과 같은 작은 NFA 조각으로 만듭니다:

- **문자 $\underline{a}$**: $S_0$에서 $a$를 읽으면 $S_1$으로 이동.

- **선택 ($r | s$)**: 시작 지점에서 $\epsilon$(입력 없이 이동)을 통해 $N(r)$ 경로와 $N(s)$ 경로로 갈라짐.

- **반복 ($r^*$)**: $N(r)$을 거친 후 다시 시작 지점으로 돌아오거나, 아예 건너뛰는 $\epsilon$ 경로를 추가.

## Thompson's Construction

**Thompson's construction** 알고리즘은 정규 표현식(RE)의 구조를 그대로 따라가며 작은 단위의 NFA 조각들을 조립하는 **구문 기반(Syntax-driven)** 방식입니다.

쉬운 이해를 위해 `a(b|c)*`를 예로 들어 단계별 구축 과정을 설명해 드립니다.

### 1단계: 기본 문자(Symbol) NFA 생성

먼저 RE에 등장하는 개별 문자(`a`, `b`, `c`)에 대한 가장 기초적인 NFA를 만듭니다.

- **구성**: 시작 상태에서 해당 문자를 읽고 종료 상태로 가는 형태입니다.

### 2단계: 선택 연산 (Alternation, `b|c`) 적용

두 개의 NFA($N(b)$, $N(c)$)를 하나로 합쳐 "b 또는 c"를 선택할 수 있게 만듭니다.

- **구조**: 새로운 시작 상태 $S_0$를 만들고, **$\epsilon$-transition(입력 없이 이동)**을 통해 $N(b)$나 $N(c)$ 중 하나를 선택해 들어가게 합니다.

- **결과**: 두 경로가 끝나는 지점에 새로운 종료 상태 $S_f$를 두고 다시 $\epsilon$으로 연결합니다.

### 3단계: 반복 연산 (Kleene Star, `(b|c)*`) 적용

방금 만든 `b|c` NFA에 0회 이상 반복 기능을 추가합니다.

- **피드백 루프**: 기존 NFA의 끝에서 다시 시작 지점으로 돌아가는 $\epsilon$ 경로를 추가하여 반복을 구현합니다.

- **0회 반복(건너뛰기)**: 시작 지점에서 바로 종료 지점으로 가는 $\epsilon$ 경로를 추가하여 빈 문자열($\epsilon$)도 허용하게 합니다.

### 4단계: 결합 연산 (Concatenation, `a` + `(b|c)*`) 적용

마지막으로 앞서 만든 `a` NFA와 `(b|c)*` NFA를 순서대로 이어 붙입니다.

- **연결**: `a` NFA의 종료 상태와 `(b|c)*` NFA의 시작 상태를 $\epsilon$으로 연결합니다.

### 최종 결과물 분석

이 과정을 거치면 `a(b|c)*`에 대한 거대한 NFA가 완성됩니다.

- **상태 번호 재지정**: 각 조각을 합칠 때마다 상태 번호가 중복되지 않도록 고유한 번호를 새로 부여합니다.

- **자동화의 장점**: 사람이 직접 설계하면 훨씬 단순한 오토마타를 만들 수도 있지만, 이 알고리즘을 사용하면 기계적으로 모든 RE를 NFA로 변환할 수 있어 **스캐너 생성을 자동화**할 수 있습니다.
