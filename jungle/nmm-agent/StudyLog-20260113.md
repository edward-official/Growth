## 부하 테스트 시나리오에 대한 관점
부하 테스트의 핵심은 명확한 테스트 시나리오입니다.
단순히 사용자 수를 늘리는 방식이 아니라, 모듈성과 내부 처리 부담을 검증할 수 있는 시나리오가 필요합니다.
특히 사용자 요청 수는 많지 않지만, 하나의 요청이 여러 워크플로우 실행을 유발하는 상황을 가정하는 것이 중요합니다.
예를 들면 연산 비용이 큰 Heavy Work와 상대적으로 가벼운 Light Work를 여러 개 정의한 뒤, 다양한 작업을 랜덤으로 실행하는 방식입니다.
이를 통해 실제 서비스 환경과 유사한 부하를 재현할 수 있습니다.

## 부하 테스트 결과 기록
부하 테스트 결과는 최대한 상세히 기록하는 것이 좋습니다.
시나리오별로 전체 수행 시간, 평균 및 최대 CPU 사용량, 메모리 사용량 등을 정리하고, 가능하다면 표와 그래프로 시각화하는 것이 바람직합니다.
대기업 환경에서는 항상 트래픽이 몰리는 상황을 기본 전제로 시스템을 평가합니다.
따라서 백엔드 개발자는 항상 최대 사용량을 기준으로 설계하고, 이를 검증하는 테스트를 수행해야 합니다.

## 쿠버네티스와 오픈소스 배포를 선택한 이유
쿠버네티스 기반 오픈소스 배포의 목적은 실제로 다른 팀이나 기업 환경에서 쉽게 설치하고 사용할 수 있는지를 검증하는 데 있습니다.
문서만 전달했을 때, 추가 설명 없이 설치가 가능해야 합니다.
이를 위해 소스 코드를 직접 수정하지 않아도 되도록 설정 값을 외부로 분리하고, 각 환경에 맞게 조정 가능한 커스텀 요소를 제공해야 합니다.
내부 구현을 보지 않아도 실행할 수 있도록 충분한 추상화와 포장이 필요합니다.

## 왜 쿠버네티스인가
쿠버네티스는 자원 효율성을 높이고, 트래픽 변화에 따라 자동으로 스케일 업과 스케일 다운을 지원하는 플랫폼입니다.
또한 기업 환경과 대규모 사용자 트래픽을 전제로 한 서비스에 적합한 인프라입니다.
모든 경우에 완벽히 적합하지는 않지만, 많은 기업이 이미 보유하고 있는 환경이기 때문에 실제로 사용해보고 검증할 가치가 있는 선택지라고 볼 수 있습니다.
